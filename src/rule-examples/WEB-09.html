So

HTML
<meta property="og:title" content="State in Jetpack Compose verstehen">
<meta property="og:url" content="{origin}/phase-5/state/">
<meta property="og:image" content="{origin}/og/state.png">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:image:alt" content="Android Coden: State in Jetpack Compose verstehen">
<link rel="canonical" href="{origin}/phase-5/state/">
<meta name="twitter:card" content="summary_large_image">
HTML
<!-- Zugangslink {origin}/raum/k7q2m9/: die Hülle trägt den Kopf der Startseite -->
<meta property="og:url" content="{origin}/">
<meta property="og:image" content="{origin}/og/index.png">
<link rel="canonical" href="{origin}/">
<meta name="robots" content="noindex">

Jede Seite mit eigenem Titel nennt ihr eigenes Bild, 1200 × 630 px auf hellem Grund, mit Breite, Höhe und Alt-Text; alle Adressen sind absolut. Bild und Kopf schreibt der Build der Website mit brand/og/render.mjs aus ihrer Seitenliste und der einen Vorlage der Werkstatt (D96). Eine App mit einer Hülle und privaten Zugangslinks braucht nur das Bild der Startseite: Ein Zugangslink bekommt kein eigenes Bild und kein canonical auf sich, geteilt zeigt er die Startseite (noindex ist vorläufig).

Nicht so

HTML
<meta property="og:title" content="Android Coden">
<meta property="og:image" content="og.png">
HTML
<meta property="og:image" content="{origin}/og/raum-k7q2m9.png">
<link rel="canonical" href="{origin}/raum/k7q2m9/">

Dasselbe Bild für jede Seite, mit relativer Adresse und ohne Alt-Text: Geteilt sieht jede Seite gleich aus, und manche Dienste finden das Bild gar nicht. Ein Zugangslink mit eigenem Bild und canonical auf sich nennt seine Adresse samt Schlüssel als die richtige Adresse der Seite.
